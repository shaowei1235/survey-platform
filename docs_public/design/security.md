# 権限・セキュリティ設計

<span class="status-chip">Design / Security</span>

## セキュリティ境界

このプロジェクトでは「画面にボタンがない」ことを権限の根拠にしません。リクエストごとに認証主体、ロール、部門スコープ、対象リソースを確認し、条件を満たした後で SQL を組み立てます。

## 認証

| 項目 | 設計 |
| --- | --- |
| ログイン | 社員番号 + パスワード |
| パスワード | argon2id、ランダム salt |
| Access token | JWT、15 分 |
| Refresh token | 32 byte のランダム値、7 日 |
| Refresh 保存 | SHA-256 ハッシュだけを DB に保存 |
| 権限情報 | JWT へ固定せず、毎リクエスト DB から取得 |

権限を JWT に埋め込まないため、ロール変更後にアクセストークンの有効期限まで古い権限が残る問題を避けられます。

## 認可の順序

1. トークンを検証する。失敗時は `401 UNAUTHENTICATED`。
2. 操作に必要なロールを確認する。失敗時は `403 FORBIDDEN_ROLE`。
3. 指定部門が利用者のスコープ内か確認する。失敗時は `403 FORBIDDEN_SCOPE`。
4. 許可された部門 ID を WHERE 条件へ含めてデータを取得する。

「範囲外なので空配列を返す」という実装は採用していません。権限違反とデータ 0 件を区別し、監査しやすくするためです。

## 部門スコープ

| ロール | 分析できる範囲 |
| --- | --- |
| 人事企画 | 企業内の全部門 |
| 経営層 | 企業内の全部門、読み取りのみ |
| 部門長 | 割り当て部門と、その配下組織 |
| 一般従業員 | 分析 API は利用不可 |

複数ロールがある場合、許可範囲は和集合で計算します。部門長の配下組織は再帰 CTE で展開し、すべての分析クエリへ `department_id IN (scope_ids)` を適用します。

## 匿名化

### 集計セル

- 有効回答数 `n < 5` の場合、平均値を `null` にする。
- 部門長へ返す応答では、マスクセルの n も `null` にする。
- n=0 は「まだ回答がありません」として少人数マスクと分ける。
- 部の値は配下課を合算してから閾値を判定する。
- Excel 出力も同じ集計関数を利用する。

### 自由記述

モデルへ渡す前に、メールアドレス、電話番号、社員番号を除去します。氏名やユーザー ID は結合せず、短すぎる記述は破棄し、1 件 200 文字・最大 30 件に制限します。ログへは件数だけを残し、本文は記録しません。

## AI の安全設計

<ol class="journey">
  <li>固定意図を検証</li>
  <li>部門スコープを検証</li>
  <li>SQL で集計</li>
  <li>記述を匿名化</li>
  <li>evidence を構築</li>
  <li>結論だけを生成</li>
</ol>

モデルに未フィルタの回答テーブルを渡さず、任意の Text-to-SQL も許可しません。モデルが返した数値と evidence の差が許容範囲を超えた場合は `AI_NUMBER_MISMATCH` とし、文章だけを成功扱いにしません。

## ログと秘密情報

| 記録する | 記録しない |
| --- | --- |
| `user_id`、`survey_id`、`intent` | パスワード、Access / Refresh token |
| `error_code`、`ai_run_id` | 自由記述の全文、完全な回答 payload |
| 処理結果の状態 | LLM API key、JWT secret |

秘密情報はコードやリポジトリへ置かず、実行環境の設定で注入します。

公開環境では、Neon の接続情報と JWT secret を Lambda の暗号化された環境変数として管理しています。値は Git、README、CloudWatch Logs に出しません。IAM role は Lambda の実行とログ出力に必要な最小権限に限定し、Lambda は VPC に入れず Neon へ TLS 接続します。

AI 分析機能の安全設計は実装とテストに残していますが、ポートフォリオ本番は `LLM_ENABLED=false` です。通常の認証、回答、匿名集計、Excel 出力は外部 AI API を呼びません。
