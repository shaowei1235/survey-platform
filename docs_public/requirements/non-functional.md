# 非機能要件

<span class="status-chip">Requirements / Quality attributes</span>

## 設計を左右した品質特性

このシステムでは、速度や見た目だけでなく、**機密性・追跡可能性・変更容易性**を業務要件と同じレベルで扱いました。特に、従業員の自由記述と小規模部署の集計は、機能が動くだけでは受け入れられません。

## セキュリティとプライバシー

| 項目 | 要件 | 実現方針 |
| --- | --- | --- |
| 認証 | 社員番号とパスワードで本人を識別 | argon2id、短寿命 JWT、リフレッシュトークンのローテーション |
| 認可 | 画面非表示だけに依存しない | API 入口でロールと部門スコープを検証 |
| 小サンプル保護 | n&lt;5 の具体値を見せない | 平均値を `null`、マスクフラグを明示 |
| 自由記述 | 個人識別情報を分析へ渡さない | メール・電話・社員番号を除去し、件数と長さを制限 |
| ログ | 機密情報を記録しない | パスワード、トークン、自由記述全文、全回答を記録対象外にする |
| 通信 | 本番経路を暗号化 | HTTPS を必須とし、許可 Origin を環境変数で限定 |

## 追跡可能性

AI 分析の成功結果は、実行者、アンケート、意図、部門スコープ、集計条件、使用した evidence に遡れるよう `ai_runs` に保存します。ダッシュボードは常に回答データから再計算し、過去の AI 出力を集計の正本にはしません。

この分離により、次の二つを両立します。

- 現在の数値は最新データから再計算できる。
- 過去の AI 結論は、その時点の入力と根拠を監査できる。

## 性能とスケール

実運用規模が確定していない段階では、推測値を確定値として扱わず、設計・検証用の基準を置きました。

| 項目 | 設計時の基準 |
| --- | --- |
| 従業員 | 2,000 人 |
| 部門 | 50 部門 |
| 設問 | 40 問 |
| 回答 | 2,000 件 / アンケート |
| クロス集計 | P95 3 秒未満を目標 |
| AI 分析 | 上流を含め P95 35 秒未満を目標 |

これらは容量計画のための暫定値です。匿名化の境界値テストやクエリ設計には利用しますが、正式 SLA とは区別しています。

## 信頼性と失敗時の振る舞い

- DB や LLM に障害がある場合、根拠のない代替値や文章を生成しない。
- LLM のタイムアウトや上流エラーは、業務エラーコードとしてフロントへ返す。
- 回答 0 件では LLM を呼ばず、データ不足を明示する。
- 公開後のアンケート構造をロックし、保存済み回答との契約を維持する。
- 再回答は DB の一意制約と API の競合応答で防止する。

## 保守性と拡張性

| 関心 | 設計 |
| --- | --- |
| 設問タイプ追加 | `type` レジストリへ描画・検証を追加し、保存形式は維持 |
| 多言語化 | UI 文案を locale 別リソースへ分離し、設問は `props.i18n` を拡張点にする |
| 認証方式変更 | 認証モジュールと RBAC を分離し、将来 OIDC を追加可能にする |
| LLM ベンダー変更 | OpenAI 互換 HTTP API と環境変数で接続先を切り替える |
| デプロイ先変更 | フロントの API URL と API ランタイムを環境変数で切り替える |

## UX とアクセシビリティの基準

- 管理画面と回答画面の既定言語を日本語に統一する。
- 回答画面では所属属性を入力させず、紐づけ方を説明する。
- 回答進捗、必須項目、空状態、マスク状態を文章でも判別できるようにする。
- 色だけに依存せず、状態名とエラーメッセージを併記する。
- エディタではドラッグ操作に加えクリック追加とキーボードの Undo / Redo を提供する。
