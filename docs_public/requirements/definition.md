# 要件定義

<span class="status-chip">Requirements / To-Be</span>

## プロダクトの目的

人事が ES アンケートを作成・公開し、従業員が回答し、権限を持つ利用者が匿名化された集計と根拠付き分析を確認できる状態を、システム内で完結させます。

要件として設計・実装した AI 分析は任意機能です。AWS 公開環境では、信頼性とコストを優先して `LLM_ENABLED=false` とし、認証、回答、匿名集計、Excel 出力を本番の提供範囲としています。

## 対象範囲

### 第一期に含めるもの

- 組織・従業員・ロールの管理
- アンケートの作成、保存、公開、終了、下書き削除
- 公開中アンケートへの回答と重複回答の防止
- 部門 × 設問のクロス集計、年代・職級フィルタ
- 部から配下課へのロールアップ集計
- n&lt;5 のセルマスクと、同じルールを使う Excel 出力
- 部署別の対象人数・回答済・未回答の可視化
- 自由記述の構造化要約と固定意図の分析
- 日本語 UI と将来の多言語化に備えたリソース分離

### 意図的に含めないもの

- 任意の自然言語を SQL に変換する機能
- RAG ナレッジベース
- SSO / 外部 IdP、HRIS との自動同期
- 画面上の言語切替
- ES 以外を保証する汎用フォームマーケットプレイス
- AI によるアンケート自動生成

スコープ外を明記した理由は、権限・匿名化・根拠照合という品質上の核心を、第一期で検証可能な大きさに保つためです。

## 利用者と責務

| ロール | 主な操作 | データ範囲 |
| --- | --- | --- |
| 人事企画 | 組織管理、アンケート作成・公開、全社分析 | 全社。ただし匿名化ルールは適用 |
| 経営層 | 集計と分析の参照 | 全社、読み取り専用 |
| 部門長 | 自部門の集計と分析の参照 | 所属部門と配下組織 |
| 一般従業員 | 公開中アンケートへの回答 | 本人の回答のみ |
| システム管理者 | アカウントとロール管理 | 個人回答の任意閲覧は提供しない |

## 中核となる業務要件

| ID | 要件 | 設計上の答え |
| --- | --- | --- |
| BR-01 | アンケート運用をシステム内で完結する | `draft → published → closed` の状態遷移 |
| BR-02 | 分析属性は組織マスタを正とする | 回答送信時に部門・職級・年代をスナップショット |
| BR-03 | 権限内で部門 × 設問を比較できる | 分析クエリへ部門スコープを必ず付与 |
| BR-04 | 小サンプルを保護する | 有効回答数 n&lt;5 の平均値を非開示 |
| BR-05 | 権限をサーバー側で強制する | 範囲外アクセスを 403 として拒否 |
| BR-06 | 自由記述を構造化する | 課題、傾向、匿名化済み引用として返す |
| BR-07 | 経営質問へ短時間で答える | 固定分析意図で低得点項目と原因を返す |
| BR-08 | AI の結論を検証可能にする | SQL 集計由来の evidence を応答へ同梱 |
| BR-09 | 回収状況を個人名なしで把握する | 部署別の対象・回答済・未回答を集計 |

## 機能要件の分解

### アンケート作成

設問を `fe_id`・`type`・`props` から成るコンポーネントリストとして保存します。管理画面では追加・削除・並べ替え・プロパティ編集を行い、回答画面は同じ契約を読み取って描画します。公開後は設問構造をロックし、回答との不整合を防ぎます。

### 回答

ログイン済みかつ未回答の従業員だけが送信できます。クライアントから部門属性が渡されても採用せず、サーバーが組織マスタから取得した値を回答に保存します。

### 集計・匿名化

リッカート設問の平均と有効回答数を部門単位で算出します。部は配下課を合算し、各セルは合算後の n で開示可否を判定します。回答 0 件は「非開示」ではなく「まだ回答がありません」と区別します。

### 根拠付き分析

第一期の自然言語分析は、`dept_low_score_and_causes` という固定意図に限定しました。意図と権限を判定し、SQL 集計と匿名化済み引用を evidence にまとめた後でのみ LLM を呼び出します。

## 受入条件

1. 人事がアンケートを作成・公開し、従業員が回答、終了まで操作できる。
2. 回答属性は組織マスタと一致し、画面から編集できない。
3. 部門長の範囲外アクセスは 403 で拒否される。
4. n&lt;5 のセルは平均値を表示せず、部門長には n も返さない。
5. 部の集計は配下課をロールアップし、0 件と少人数を区別する。
6. Excel 出力にも画面と同じマスクルールを適用する。
7. AI の結論には集計根拠が付き、数値不一致時は結論を返さない。
8. UI の既定言語は日本語で、文案とロジックが分離されている。

## 追跡可能性

| 課題 | 要件 | 設計 | 主な確認 |
| --- | --- | --- | --- |
| 小規模部署の特定 | BR-04 | セル単位の n&lt;5 マスク | n=3 / n=5 / n=0 の境界値 |
| 他部門データの閲覧 | BR-05 | クエリ前の部門スコープ検証 | 範囲外 403、配下部門の和集合 |
| 属性の誤入力 | BR-02 | 回答時点のマスタスナップショット | リクエスト属性を無視すること |
| AI の数字の捏造 | BR-08 | evidence との数値照合 | 不一致時の `AI_NUMBER_MISMATCH` |
